# DZ2 — Why system-prompt hardening alone is not enough

The probabilistic layer (a hardened system prompt) and the deterministic layer (server-side scope enforcement) are tested in isolation with the SAME crafted "developer override" payload.

- **(a) Hardening only:** the hardened prompt is active but the broad tools are still live — driven through the n8n webhook with `vulnerableMode:false` while the backend flag is Enabled. If the prompt were the only defense, this is what a real attacker faces.
- **(b) Secure build:** the exact same payload through the real proxy with the flag Disabled, so the server returns 403 no matter what the model decides.

This bypass is **probabilistic**: in the red-team this payload bypassed the hardened prompt on 2 of 3 trials (`redteam/report.md`, dev_override under "hardening_only"), while the secure build blocked it on every trial (0/2). A defense that works most of the time is not a security guarantee.
